# 命令执行模型（待改）

## 现象

- 执行命令和读取输出被拆成两步：先发起，超时后转后台 job，再查输出。
- 需要预估命令运行时间，估长估短都不合适。
- 短命令也可能被拆两步，长命令会显得卡住。

## 期望

- 发起命令后一直等到进程退出，Exit 0 / Exit 1 一出现就立刻返回输出。
- 不靠固定等待时间推进下一步；需要中途停止时用 Esc 或全局急停。
- 只有明确要后台运行的任务才转后台。

## 现状原因

- `pwsh` 工具由 DSH 内核提供，不在本仓库源码里；宿主只负责渲染工具卡片。
- 工具执行器带超时：到点就把命令转成后台 job，模型再调 `job_output` 取增量，于是变成两步。
- 调用方再传较短的 `timeoutMs`，触发得更频繁。

## 已改

- `profiles/acp/cordis.patch.yml` 增加 `tool-pwsh` 配置：`enableRunInBackground: false`、`promoteOnTimeout: false`。
- 由 `syncDshPwshPatch()` 在 DSH 进程启动前写入，重启 DSH 进程生效。
- 效果：命令超时不再自动转成后台 job，模型也不能主动开后台，调用只等进程退出或真正超时。
- 仍未改：默认超时还是 5 分钟；超时后命令被终止，而不是继续等。

## 可选方案

1. **内核工具层改（根治）**：进程退出即返回，不再用固定超时；中断由现有 Esc / 全局急停负责。需要改 DSH bundle 或做内核补丁。
2. **宿主替换工具**：宿主自己接管 `pwsh` 工具执行，同步等进程退出，把结果回填给 ACP。改动集中在宿主，但要处理工具协议、流式输出和中断。
3. **只调默认值（缓解）**：把默认超时拉到与回合超时一致（30 分钟），绝大多数命令一步完成；死循环命令仍会占满回合。不能根治。

## 验收

- 一条 30 秒的命令只出现一次工具调用，退出后立即拿到完整输出。
- 执行中按 Esc 能中断，返回已产生的输出和中断状态。
- 不再出现“先执行、再 job_output 轮询”的固定两步。
